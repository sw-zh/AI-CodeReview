# feature/doc-viewer

## 已完成

### 固定双核与默认编排

- 建立固定的“需求 / 验收核验核心”和“交付证据核验核心”。两者是正式核验主干，不能在模板中删除、停用或跨核心移动。
- `Git Diff` 已作为交付证据核心的锁定默认能力。正式代码核验只读取冻结的 Git 范围，不执行仓库代码、构建命令或 Git Hook。
- 默认模板已包含：资料 Claim、Git Diff、可选 CI 证据、风险扫描、模型关联建议、证据裁决与 Coverage、报告草稿能力块。
- 任务绑定模板；分析运行启动时冻结模板、能力块版本、Prompt、工具授权和参数，之后修改模板不会影响历史运行。

### 自定义 Agent、工具与编排工作台

- 新增 Agent 功能块、工具授权、编排模板的数据模型、迁移、接口和工作台页面。
- 用户可创建外围 Agent，保存自定义 Prompt、输入/输出 Schema、参数 Schema 与已授权工具；后续修改采用新版本保存。
- 项目内可登记只读工具，并把工具授权给外围 Agent；密钥只保存服务端环境变量名称，不保存密钥值。
- `HTTP_QUERY` 已可在运行时执行：仅管理员能登记、仅允许服务端白名单内的 HTTPS 主机、仅 GET、禁止重定向、限制超时与响应大小。工具返回会记录为需人工确认的工具证据，并写入运行事件与 Coverage，不会单独形成正式确认结论。
- 工作台沿用现有浅色企业风格，并在“项目空间”左侧层级导航中加入“Agent 功能块”。页面支持查看双核、登记工具、创建自定义 Agent、选择能力块并调整模板顺序。
- 自定义 Agent 的模型输出仅能提出证据关联建议；最终核验结论、审批、发布与输入快照仍由既有确定性规则和人工环节控制。

### 运行可见性与模型接入

- Notebook 会在任务 ID 为真实 UUID 时读取最新分析运行、冻结编排快照与真实核验结果；无真实任务时保留原演示数据，方便产品展示。
- 分析运行结束后，若冻结模板启用了“报告草稿”能力块，Worker 会自动生成 DRAFT 报告、写入运行事件和审计记录；提交、审批、发布仍必须经过既有人工流程。
- 新增 DeepSeek 生成模型适配：配置 `GENERATION_PROVIDER=deepseek`、`DEEPSEEK_API_KEY` 后，可通过 Chat Completions 的 JSON 输出生成证据关联建议和证据问答结果。
- 模型调用记录会使用实际配置的模型名；未配置 API Key 时会返回明确的“模型未配置”错误，不会回退为不透明调用。

## 当前在做

- 等待真实 DeepSeek API Key 后进行联调：以冻结项目快照验证结构化输出、模型调用记录和降级记录。功能代码已完成，不需要先提供 Key 才能继续本地开发。
- 已确认后续总体方向：固定双核仅服务于“交付核验”；项目态势/研发总结与安全基线属于读取结构化事实和正式记录的外围能力。当前正在进行架构收敛，尚未开始这一轮数据模型、接口和界面改造；详细约束见《项目整体核验与后续开发方向》。

## 尚未实现 / 明确不做

- 不执行任意 HTTP 方法、重定向、未在白名单中的端点，或由模型决定 URL/参数的网络调用；若未来需要写工具，必须另加独立审批令牌和授权策略。
- 前端暂未提供既有自定义 Agent 的版本编辑、停用和任务模板绑定表单；服务端已提供能力块版本创建和任务模板绑定接口。这属于后续“更自由编排”阶段，不改变当前的固定双核边界。
- 不提供任意本地命令执行、自动构建、自动运行测试或自动发布能力；这些行为不属于只读交付核验的授权范围。
- 尚未实现外部 Issue、Milestone、PR 和文档来源的同步镜像、研发事项/交付项关联、项目态势总结、日报/周报、独立安全基线运行配置与对应正式记录。
- 当前 `Git Snapshot` 仍是全部分析运行的全局前置条件；后续应收敛为仅 `DELIVERY_VERIFICATION` 强制，项目总结和安全基线必须使用各自的输入快照规则。
